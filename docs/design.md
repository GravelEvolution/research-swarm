# 科研蜂群实现边界

> 历史初版设计。2026-09-26 用户已改为“任务会话 + 单输入框 + 三维结构 + 自主研究”。当前界面与交互以 conversation-contract.md 和 README.md 为准；下面的六页面和四个固定检查点不用于当前工作区。

依据用户给出的完整产品规格实现一个可在 Windows 本机运行的科研协作工具。沿用 ai-access 的检索代码、SQLite 论文和切面结构；新产品保存在本目录，原始研究数据保持可回溯。界面使用真实 Semi Design React 组件，白色、浅灰、蓝色标准工具样式，无主题动效。

科研层拥有节点、需求、研究循环、版本、证据和用户检查点。已有 Python LLM 配置可复用，也可在设置中配置 OpenAI-compatible/Anthropic 端点。工具执行通过明确白名单；不引入通用编码 agent，不让 DSH 决定研究流程。DSH 是可选技术，本实现直接提供受限科研工具层。

九阶段：需求边界、论文检索、结构形成、推荐筛选、研究思考、需求分解、节点执行、对比判断、研究交付。四检查点顺序为需求确认、推荐流筛选、对比结论确认、最终输出确认。AI 内容均为候选判断，最后两次确认由用户操作。

所有已导入切面节点有对应 agent。一个研究需求可以选中多个范围，逐级明确需求，叶子任务执行后写入本项目 SQLite 的节点输出切面，再逐级汇总。每次执行绑定节点版本与轮次。暂停停止派发，回滚/修改使旧执行失效。失败有日志和重试；进程重启保留数据并以暂停状态恢复。

需求、运行日志、节点输入/输出、证据 ID、论文 ID 和定位、用户决策、失效历史均持久化。影响预览返回下游节点数量，提交时检查版本。导出包含报告 Markdown、结构化数据 JSON、证据和活动记录。没有证据的候选必须显示“无证据”；摘要证据不得显示成全文或实验验证。

六页面与 Drawer/Modal 操作遵循用户规格。顶部固定当前阶段、活动节点、用户事项和暂停；工作台有 9 阶段 Steps、检查点卡片、倒序活动；需求可编辑；蜂群 Tree 和节点详情；论文树表与证据；推荐分组、分项分数和标记；报告有结论、证据和未决问题。

本地数据核验模式仅执行真实数据库统计、证据整理和可复现性材料检查，明确不声称模型研究/实验已执行。模型模式调用用户端点并约束结构化输出。实验任务须提供真实输入、执行协议与产物，无法运行时记录缺失条件，绝不捏造指标。

验收覆盖：现有 51 篇论文导入；四检查点不能被恢复按钮绕过；子任务完成后才汇总；暂停及回滚拒绝迟到结果；影响预览和修改版本一致；人工标记保存；报告导出受最终确认限制；浏览器走通六页面及关键操作。
